# Holdfast Panel

Windows-приложение: контрольная панель для серверов, на которых стоит
[holdfast](https://github.com/viktorplus/holdfast). Приложение подключается к
каждому серверу по SSH и вызывает на нём `holdfast` и обычные команды Linux;
агента на сервере нет. Серверов можно добавлять сколько нужно, они показываются
списком слева.

## Запуск

```sh
python -m venv .venv
.venv\Scripts\pip install -e .[dev]
.venv\Scripts\python -m holdfast_panel
```

Нужен Python 3.11.4 или новее.

## Что умеет

**Список серверов и подключение.** «Добавить сервер»: имя, адрес, порт, логин,
пароль. Панель показывает отпечаток ключа сервера для сверки, один раз по
паролю ставит свой ключ в `~/.ssh/authorized_keys`, проверяет вход по ключу и
забывает пароль. Дальше вход только по ключу; если отпечаток сервера изменился,
подключение блокируется.

**Монитор.** ОС, время работы, нагрузка, процессор, память, диски, процессы по
загрузке и контейнеры Docker. В списке серверов у каждого видно, в сети ли он и
что требует внимания.

**Диагностика.** По кнопке: установлен ли holdfast, конфигурация, свежесть
последнего бэкапа (журнал читается там, где его держит holdfast этого сервера),
свободное место, расписание (cron или systemd-таймер), состав копии
(`backup --dry-run`). Аудит безопасности (`holdfast audit`) включается отдельной
галочкой: он сохраняет своё состояние как базу для сравнения, и запуск из панели
потратил бы изменения, о которых должен сообщить ночной аудит.

**Бэкапы и три места для копий.** Снимки можно смотреть и переносить между:
- *на сервере* (`/opt/backups`);
- *на этом компьютере* (папки, которые вы добавили в «Хранилища…»);
- *удалённым хранилищем* (rclone-путь вида `shared:backups`; их может быть
  несколько, rclone настраивается на сервере).

Из вкладки: создать бэкап (сначала показывается состав), проверить копию,
восстановить (проверка → план → подтверждение → восстановление), скопировать
снимок в другое хранилище, поднять новый сервер из снимка с нуля.

**Состав архива.** Режим (auto/manual) и список исключений формой, весь
`holdfast.toml` текстом. Перед сохранением показываются изменения; сохраняется
копия `.bak-…`; если после правки бэкап перестал запускаться, файл
возвращается.

**Шаблоны.** Готовые: первичная установка сервера (обновление, пакеты, Docker,
holdfast, ключ шифрования, cron), обновление системы, fail2ban, ufw, WordPress +
MySQL, PostgreSQL, Portainer. Свои шаблоны — JSON, правятся в редакторе. Перед
запуском видны точные команды (пароли скрыты); запустить можно на выбранном
сервере или на всех по очереди.

**Журнал.** Что панель делала, где и чем закончилось.

## Как защищены секреты

- Пароль сервера используется один раз и нигде не хранится.
- Ключ панели (`%APPDATA%\HoldfastPanel\id_ed25519`) зашифрован; его пароль
  лежит в диспетчере учётных данных Windows.
- **Приватный ключ шифрования бэкапов (age) панель не хранит.** Для проверки или
  восстановления вы выбираете файл ключа; он копируется на сервер в закрытый
  файл только на время операции и стирается (`shred`) в любом исходе, в том числе
  при обрыве связи. Для постоянного хранения держите ключ вне сервера.
- Значения переменных шаблонов экранируются (`shlex.quote`) и не становятся
  командами; переменные типа password скрываются в предпросмотре, выводе и
  журнале.

## Проверка

```sh
.venv\Scripts\python -m pytest
.venv\Scripts\python -m ruff check .
```

Тесты поднимают настоящий SSH-сервер в процессе теста и выполняют команды в Git
Bash с временным `HOME`, поэтому на Windows нужен Git for Windows
(`C:\Program Files\Git`) или переменная `GIT_BASH` с путём к `bash.exe`; иначе эти
тесты пропускаются. Окно проверяется на офлайн-платформе Qt.

Не проверено автоматически: установка на реальный сервер, `rclone`, `docker
compose` и восстановление на настоящей системе — это нужно один раз пройти
вручную на тестовом сервере.

## Известные ограничения

- Если связь с сервером оборвалась посреди долгой команды, сама команда на
  сервере продолжает выполняться (панель закрывает канал, но не убивает
  процесс). Перед повтором проверьте, что предыдущий запуск закончился:
  например, `apt` держит блокировку, а восстановление повторяемо, но не должно
  идти дважды одновременно.
- Первое подключение доверяет отпечатку, который вы подтвердили (TOFU). Файл
  `servers.json` не подписан: вредоносная программа с правами вашего
  пользователя может подменить в нём адрес и отпечаток. Защита этого
  уровня — права на папку `%APPDATA%\HoldfastPanel`.
- Приватный ключ панели лежит в `%APPDATA%\HoldfastPanel` с наследуемыми правами;
  пароль к нему хранится в диспетчере учётных данных Windows. Любой процесс
  вашего пользователя может прочитать и то и другое.
- Имя проекта compose берётся из папки (как при обычном `docker compose up`).
  Если на старом сервере проект запускали под другим именем, восстановление на
  новом сервере по умолчанию не сможет его угадать: используйте обычное
  восстановление и запустите контейнеры вручную с нужным именем.
- Проверено на тестовом SSH-сервере и на настоящем выводе Debian; не проверено
  на реальных серверах: установка по шаблону, `rclone`, `docker compose` и
  восстановление. Это нужно один раз пройти вручную на тестовой машине.
